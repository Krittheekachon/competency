# Organization chart

The admin organization screen opens the chart first. Existing catalog editors remain under “จัดการรายการองค์กร”. The chart uses `worklines`, academic `job_families`, and `support_departments -> support_works -> support_units`. Support job families classify positions and are not drawn as departments. Branches end at their last real record; missing parent levels are not synthesized. The top “โครงสร้างองค์กร” box is a navigation heading, not a database entity.

`OrganizationChartService` assembles the admin-only Inertia `organizationChart` prop. Profile membership initially follows `UserOrganizationPresenter`; ambiguous legacy matches are omitted rather than assigned by guesswork. A parent box lists its direct members, while child boxes show their own members. A head is shown only when explicitly assigned.

`organization_chart_assignments` stores explicit heads and whether chart membership overrides profile membership. `organization_chart_members` stores those explicit members. These assignments affect the chart only: they do not move users' profile affiliations, change roles, or update assessment/IDP reviewer chains. Switching back to profile members removes the chart override. Removing a user clears their head/member references through foreign keys.

Organization create/rename/delete actions reuse the existing admin structure endpoints. Support renames synchronize legacy profile paths transactionally. Existing delete endpoints also enforce child/member/head/reference protection, including profile members hidden by a chart override. Organization rows are locked during deletion. Assignment saves lock the source row too. Node keys are validated against real organizational records, not accepted as arbitrary table names.

The existing typed tables enforce the direction of the hierarchy; there is no arbitrary reparent endpoint, so users cannot introduce a cycle. Adding entirely new kinds of level or moving a unit outside its existing parent type would need a separate schema/domain decision.

The readable view opens at 100% with roots expanded and deeper branches collapsed. Root groups use responsive columns; descendants stack vertically with elbow connectors. Node names are 17px and secondary text 13px before any explicit zoom. “มุมมองเริ่มต้น” restores that state. “พอดีหน้าจอ” explicitly fits the currently expanded tree to the viewport's width and height; it is never triggered by initial load or branch expansion. Expanding a branch preserves zoom and brings its parent card back into the canvas viewport.

Personnel and management forms share a right-side panel (480px on desktop, full width at 900px and below). Opening moves keyboard focus into the panel, Tab stays within it, and Escape/close restores focus to the initiating control. A selected node stays highlighted after closing. These are frontend-only changes; routes, permissions, validation, persistence, and schema remain unchanged.

The existing default assessment template selector now initializes the editable user form from explicit chart heads. `OrganizationReviewerDefaults` uses the evaluated user's persisted canonical position/unit or uniquely matching persisted affiliation and walks nearest-to-root. It never infers a head by role or picks an ambiguous department. Missing/inactive heads, self and duplicate heads are explained; no eligible heads/ambiguous affiliations leave the old form list intact. A nonempty list requires confirmation before replacement. Form edits detach the preset so ordinary user save behavior cannot reinsert the preset's old fixed reviewers. Step-count differences are reported without truncating the available heads. New users or changed, unsaved affiliations must be saved/reopened first. This read-only preview is an admin-only Inertia prop, not a new API or automatic synchronization mode. Assessment runtime remains `user_reviewer_steps`/round snapshots; IDP behavior is unchanged. See `output/structure-reviewer-qa/REPORT.md`.
